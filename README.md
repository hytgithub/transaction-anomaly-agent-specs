# 交易业务异常诊断 Agent：共享规格仓库

本仓库保存 AgentScope 与 LangGraph 两个实现共同遵循的产品需求和智能体评测标准。这里只维护规格、契约与验收约定，不存放框架实现代码。

## 文档入口

- [产品需求文档（PRD）](docs/PRD.md) — 0.2.0-draft
- [智能体评测规范](docs/EVALUATION_SPEC.md) — 0.2.0-draft

## 项目目标

构建一个具有证据链、人工审批、受控模拟修复和修复后验证能力的交易业务诊断 Agent；使用统一评测集比较 AgentScope 与 LangGraph 的诊断质量、安全性、稳定性、耗时和成本。

## 首期范围

- 首期完整实现：支付成功，但订单状态未更新。
- 总体规划还包括：支付回调/事件重复、优惠券状态不一致、订单与库存状态不一致。
- 首期仅使用合成模拟交易数据，不连接生产交易系统或真实支付渠道。
- 模拟修复只允许重放符合条件的业务事件；每个具体操作必须由与提案发起人不同的审批账号批准。禁止 Agent 直接改库。
- 首批设计 8 个可重置评测案例，之后分阶段扩展到约 30 个、约 60 个案例。

## 协作约定

1. 先更新并固定本仓库的规格，再开始对应实现。
2. 两个实现仓库应固定引用本仓库的具体 Git commit，不以“最新版本”作为隐式依赖。
3. 两个框架共享业务服务、模拟数据、工具契约和评测器；Agent 编排与框架适配独立实现。
4. 两个实现使用相同的 DeepSeek 模型版本、核心 Prompt、生成参数、工具契约、运行限制、案例和评分标准。
5. 安全硬门槛不能被其他维度的高分抵消；所有评测失败样本应保留并分类。
6. 每次规格变更记录版本、变更内容、原因及受影响的验收项。
7. 规格中的功能描述和案例设计不代表功能已实现或测试已通过。
