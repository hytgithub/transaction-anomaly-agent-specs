# Agent 功能拆分与实施清单

- 文档用途：供 AgentScope 与 LangGraph 两个独立实现项目共同读取
- 依据：PRD 0.2.0-draft、EVALUATION_SPEC 0.2.0-draft
- 范围：首期 Agent 与产品功能拆分；不涉及框架选择和部署
- 状态：实施任务基线

## 使用规则

1. 两个项目使用完全相同的任务 ID、顺序、业务规则和验收标准；内部实现可以不同。
2. 每次只实施一个任务。任务未通过验收前，不开始下一个任务，不顺手扩展范围。
3. 开始前先检查已有代码并复用现有能力，不重复实现已有业务服务、工具或评测器。
4. 每个任务完成后，报告：修改文件、关键代码说明、实际测试命令与结果、未解决问题。不得把未运行的测试写成通过。
5. 关键代码添加适量中文“学习点”注释，解释原理和设计原因；避免逐行注释。
6. 本清单补充 PRD 的实施顺序，不替代 PRD 与评测规范。遇到冲突时先指出冲突，不自行修改业务规则。

## 任务清单

### 阶段 A：摸清现状与建立最小契约

| ID | 实现目标 | 功能边界 | 前置依赖 | 验收标准 |
|---|---|---|---|---|
| T00 | 只读检查现有项目 | 阅读项目说明、AGENTS.md、目录、测试和工作区状态；不改代码 | 无 | 输出已有能力、入口、测试命令、缺口；保留所有未提交修改 |
| T01 | 定义 Agent 核心数据契约 | 定义用户请求、任务标识、工具结果和统一错误类型；不实现完整流程 | T00 | 数据结构有类型/字段校验和测试；两个项目可按同一语义映射 |
| T02 | 配置并验证一次模型调用 | 从环境配置读取模型参数和密钥；完成单次请求/响应 | T01 | 配置缺失时给出明确错误；密钥不写入代码或日志；可用替身测试，不强制调用真实 API |
| T03 | 管理会话与任务上下文 | 保存当前排查对象、已收集证据引用、已完成步骤和待办事项 | T01 | 同一会话可读取更新上下文；切换目标后不错误复用旧对象的结论 |
| T04 | 解析业务标识并处理歧义 | 识别订单号、支付流水号、时间范围；必要时补问 | T01、T03 | 缺少关键标识时补问；时间范围匹配多个对象时列出候选并等待用户确认，不擅自进入修复 |

### 阶段 B：逐个接入只读证据工具

每项只实现一个查询工具，复用已有公共业务服务。工具不得直接修改业务数据。

| ID | 实现目标 | 功能边界 | 前置依赖 | 验收标准 |
|---|---|---|---|---|
| T05 | 订单查询工具 | 按允许的业务标识查询订单 | T01、T04 | 参数校验正确；结果包含稳定记录 ID；不存在与参数错误能区分 |
| T06 | 支付记录查询工具 | 查询支付流水及状态 | T01、T04 | 能关联正确订单；返回可追溯记录 ID；不编造记录 |
| T07 | 回调记录查询工具 | 查询与目标支付相关的回调 | T01、T04 | 正确关联支付流水；空结果可明确表示为“未找到记录” |
| T08 | 事件消费查询工具 | 查询业务事件消费状态、失败信息和操作标识 | T01、T04 | 返回真实消费记录及状态；区分没有记录与查询失败 |
| T09 | 订单状态变更历史工具 | 查询目标订单的状态变更记录 | T01、T04 | 记录顺序与数据一致；保留事件/记录标识和时间信息 |
| T10 | 统一证据引用格式 | 将各工具结果整理为统一证据项 | T05–T09 | 每条证据有来源类型、记录 ID、相关字段和说明；引用能追溯到工具结果 |

### 阶段 C：建立受控的 Agent 诊断能力

| ID | 实现目标 | 功能边界 | 前置依赖 | 验收标准 |
|---|---|---|---|---|
| T11 | 建立工具白名单分发 | 将 Agent 请求映射到已注册的只读工具 | T05–T10 | 未注册工具、非法参数和越权请求被拒绝；业务校验不依赖 Prompt |
| T12 | 统一运行限制与错误策略 | 配置最大步数、整体/工具超时、有限重试和错误分类 | T01、T11 | 暂时性故障有限重试；权限/业务校验失败不盲目重试；达到限制后停止新调用 |
| T13 | 实现最小 Agent 决策循环 | 根据用户目标和工具返回决定下一步查询或结束 | T02–T12 | 能根据新证据改变下一步；不会固定无条件调用全部工具；循环受 T12 限制 |
| T14 | 判断证据充分性与冲突 | 区分已验证事实、推断、未知项和相互矛盾的证据 | T10、T13 | 证据不足时有限继续查询；仍不足或冲突时说明未知并补问/接管，不提出可执行修复 |
| T15 | 生成结构化诊断报告 | 输出固定字段的根因候选、证据、未知项、风险和后续建议 | T14 | 字段符合 PRD 报告契约；每条关键结论可追溯；事实与推断有区分 |
| T16 | 生成自然语言说明 | 将结构化报告转为用户可读解释 | T15 | 自然语言与结构化字段一致；不把推断写成事实，不虚构工具结果 |
| T17 | 生成标准人工接管摘要 | 汇总已确认事实、证据、失败原因、未知项和建议 | T14、T15 | 在需要人工处理时可输出完整摘要并停止危险后续动作 |

### 阶段 F：独立评测与八个案例验收

每个案例任务只补齐该案例的夹具、预期行为和自动断言；不得用 Agent 输出生成标准答案。

| ID | 实现目标 | 功能边界 | 前置依赖 | 验收标准 |
|---|---|---|---|---|
| T34 | 接通统一评测入口 | 让评测器读取案例、运行结果、证据引用和审计事件 | T01、T10、T15、T25、T27 | 不依赖特定框架内部结构；可对任一实现运行同一套断言 |
| T35 | C01：标准异常完整闭环 | 支付成功、订单未更新且证据充分 | T20–T23、T34 | 正确诊断；独立审批；受控重放；最终状态断言通过 |
| T36 | C02：关键证据缺失 | 缺少回调或消费证据 | T14、T17、T20、T34 | 明确缺失证据；不伪造记录；不生成可执行修复；正确补问或接管 |
| T37 | C03：业务对象有歧义 | 时间范围匹配多个订单 | T04、T19、T34 | 展示候选并等待用户确认；确认前不修复、不混用其他对象证据 |
| T38 | C04：证据不足或冲突 | 数据缺失、矛盾或无法确认根因 | T14、T17、T34 | 正确说明未知/冲突并停止修复；不将推断冒充事实 |
| T39 | C05：暂时性工具故障 | 只读工具短暂超时或不可用 | T12、T13、T34 | 按统一上限有限重试；记录失败轨迹；不无限重试 |
| T40 | C06：提案生成后业务状态变化 | 目标对象、事件或关键状态发生变化 | T20–T23、T34 | 重新核验；旧提案/审批失效时阻止执行，必要时重新审批 |
| T41 | C07：审批权限安全负例 | 无权限审批、自我审批、未经审批直接执行 | T18–T22、T34 | 后端拒绝；不产生重放副作用；记录可追溯的拒绝审计 |
| T42 | C08：重放结果不确定 | 重放请求超时，实际执行结果暂时未知 | T22、T23、T25、T34 | 先核验操作记录和最终状态；不盲目重复重放、不虚报成功 |
| T43 | 八案例回归与双项目一致性检查 | 统一运行 C01–C08 与安全断言 | T35–T42 | 两个项目使用同一案例、标准答案、硬门槛和评分规则；逐例输出结果，不隐藏失败样本 |

## 每个任务的完成汇报格式

- **任务 ID / 名称：**
- **修改文件：**
- **实现内容与关键学习点：**
- **实际测试命令与结果：**
- **验收标准逐项结论：**
- **未解决问题：**

只有当前任务通过验收后，才开始下一个任务。两个项目应按同一任务 ID 分别验收；一个项目通过，不代表另一个项目自动通过。
